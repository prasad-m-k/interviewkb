# Terraform Module Design Pattern

**Topic:** [[devops/topics/infrastructure-as-code]]
**Related concepts:** [[devops/concepts/terraform-patterns]], [[devops/concepts/terraform-state]], [[devops/concepts/infrastructure-as-code]]

---

## What it solves

Without modules, Terraform code is copy-pasted across environments and services. A VPC definition that appears in `dev/`, `staging/`, and `prod/` drifts apart as each gets patched independently. Modules solve this by making infrastructure reusable — write once, configure per caller.

A good module structure also enforces the right abstraction: callers express *intent* (I want a VPC with 3 private subnets and 3 public subnets), not *mechanism* (I want these specific CIDR blocks and route table entries).

---

## Module Directory Structure

```
modules/
├── vpc/
│   ├── main.tf          # resources
│   ├── variables.tf     # input variable declarations
│   ├── outputs.tf       # output value declarations
│   ├── versions.tf      # required_providers and required_version
│   └── README.md        # usage example (generated by terraform-docs)
├── eks-cluster/
│   ├── main.tf
│   ├── variables.tf
│   ├── outputs.tf
│   └── versions.tf
└── rds-postgres/
    ├── main.tf
    ├── variables.tf
    ├── outputs.tf
    └── versions.tf

environments/
├── prod/
│   ├── main.tf          # calls modules
│   ├── terraform.tfvars # environment-specific values
│   └── backend.tf       # remote state config
├── staging/
│   └── ...
└── dev/
    └── ...
```

## Template / Skeleton

### Module definition (`modules/vpc/main.tf`)

```hcl
resource "aws_vpc" "main" {
  cidr_block           = var.cidr_block
  enable_dns_hostnames = true
  enable_dns_support   = true
  tags = merge(var.tags, { Name = "${var.name}-vpc" })
}

resource "aws_subnet" "private" {
  count             = length(var.azs)
  vpc_id            = aws_vpc.main.id
  cidr_block        = cidrsubnet(var.cidr_block, 4, count.index)
  availability_zone = var.azs[count.index]
  tags = merge(var.tags, { Name = "${var.name}-private-${count.index + 1}" })
}

resource "aws_subnet" "public" {
  count                   = length(var.azs)
  vpc_id                  = aws_vpc.main.id
  cidr_block              = cidrsubnet(var.cidr_block, 4, count.index + 8)
  availability_zone       = var.azs[count.index]
  map_public_ip_on_launch = true
  tags = merge(var.tags, { Name = "${var.name}-public-${count.index + 1}" })
}
```

### Module variables (`modules/vpc/variables.tf`)

```hcl
variable "name" {
  type        = string
  description = "Name prefix applied to all resources in this module"
}

variable "cidr_block" {
  type        = string
  description = "VPC CIDR block (e.g. 10.0.0.0/16)"
  validation {
    condition     = can(cidrhost(var.cidr_block, 0))
    error_message = "Must be a valid CIDR block."
  }
}

variable "azs" {
  type        = list(string)
  description = "List of availability zones (2-3 recommended)"
  default     = ["us-east-1a", "us-east-1b", "us-east-1c"]
}

variable "tags" {
  type        = map(string)
  description = "Tags applied to all resources"
  default     = {}
}
```

### Module outputs (`modules/vpc/outputs.tf`)

```hcl
output "vpc_id" {
  value       = aws_vpc.main.id
  description = "VPC ID"
}

output "private_subnet_ids" {
  value       = aws_subnet.private[*].id
  description = "List of private subnet IDs"
}

output "public_subnet_ids" {
  value       = aws_subnet.public[*].id
  description = "List of public subnet IDs"
}
```

### Caller (`environments/prod/main.tf`)

```hcl
module "vpc" {
  source     = "../../modules/vpc"      # local path
  # source   = "git::https://github.com/myorg/terraform-modules.git//vpc?ref=v1.2.0"
  # source   = "registry.terraform.io/hashicorp/vpc/aws"  # public registry

  name       = "prod"
  cidr_block = "10.0.0.0/16"
  azs        = ["us-east-1a", "us-east-1b", "us-east-1c"]
  tags       = { Environment = "prod", Team = "platform" }
}

module "eks" {
  source            = "../../modules/eks-cluster"
  name              = "prod-eks"
  vpc_id            = module.vpc.vpc_id                # output from vpc module
  private_subnet_ids = module.vpc.private_subnet_ids   # output from vpc module
}
```

## Module Versioning

Version modules the same way you version libraries — callers pin to a version; breaking changes bump a major version.

**Git tags as versions:**
```hcl
module "vpc" {
  source = "git::https://github.com/myorg/terraform-modules.git//modules/vpc?ref=v2.1.0"
}
```

Upgrade process: bump `?ref=v2.1.0` to `v2.2.0`, run `terraform init -upgrade`, run `terraform plan`, review, apply.

**Private module registry** (Terraform Cloud / Enterprise): publish modules with version tags. Callers reference as `source = "app.terraform.io/myorg/vpc/aws" version = "~> 2.0"`.

## Complexity: Hierarchy and Blast Radius

```
Root module (environments/prod/)
  └── module.vpc
  └── module.eks
        └── module.node_groups (nested)
  └── module.rds
  └── module.iam
```

**Blast radius rule:** keep the root module blast radius manageable. A single `terraform apply` in `environments/prod/` touching 500 resources is high risk. Consider splitting: `network/`, `platform/`, `apps/` as separate root modules with separate state (see [[devops/concepts/terraform-state#Splitting State]]).

**Nesting depth:** prefer 1-2 levels of nesting. Deeply nested modules are hard to debug (the resource address becomes `module.a.module.b.module.c.aws_instance.x` which is opaque in plan output).
